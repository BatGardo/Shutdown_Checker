# Shutdown_Checker

Telegram bot for DTEK power outage schedules, hosted on Render's free plan.

- Schedule for each user's own group (черга), from the public mirror
  [Baskerville42/outage-data-ua](https://github.com/Baskerville42/outage-data-ua).
- Header: power now by schedule, and whether schedules apply or emergency outages are in effect
  (from the public channel [@esvitlo_kyiv_ua](https://t.me/s/esvitlo_kyiv_ua)).
- Always sent: schedule changes, tomorrow's schedule, emergency outages start/end.
- Options per user: `/tracker N` (status every N min), `/remind N` (before an outage),
  `/remind_on N` (before power returns).
- Deye inverters, **read-only**: grid on/off and battery SoC, each inverter to its owner chat only.
  The code refuses every Deye API call except three read endpoints.

Standard library only, no dependencies.

## Files

| File | Purpose |
|---|---|
| `main.py` | Entry point. Webhook server on Render (`/telegram`, `/health`), polling on a PC |
| `bot.py` | Bot logic: commands, schedule checks, reminders, emergency alerts, inverters |
| `dtek.py` | Schedule mirror: download, half-hour slots, report text |
| `deye.py` | Read-only Deye Cloud client and grid/SoC reading |
| `config.py` | Settings from environment / `.env` / Render Secret File |
| `storage.py` | State in a local file or as a pinned document in a private Telegram channel |
| `telegram.py` | Minimal Bot API client |
| `deye_token.py`, `Deye token.bat` | **PC only.** Logs in to Deye Cloud once and writes the access token into `.env` |
| `Run locally.bat` | Run the bot on a PC in polling mode |
| `.env.example` | Template of all settings; `.env` itself is never committed |
| `Dockerfile` | Image for Render (`TZ=Europe/Kyiv` is required, the schedule is in Kyiv time) |
| `tests/test_e2e.py` | End-to-end test with fake Telegram and Deye servers |

## What is secret and where it lives

| Value | Where |
|---|---|
| `TELEGRAM_TOKEN` | `.env` → Render Secret File |
| `STATE_CHAT_ID` | `.env` → Render Secret File |
| `DEYE_n_TOKEN` (time-limited access token) | `.env` → Render Secret File |
| Deye password, AppSecret | **Nowhere.** Typed into `Deye token.bat` on your PC, used once, not saved |
| Webhook secret | Generated by the bot on every start, not stored |

## Setup

### 1. Telegram

1. In [@BotFather](https://t.me/BotFather): `/newbot`, get the token. Use a **new bot** for Render, not the
   local test bot: two running copies of one bot break each other's updates.
2. Create a **private channel** (for example "Shutdown_Checker state"). Add the bot as an administrator
   with **Post messages** and **Edit messages of others**. The bot keeps its state there as one pinned file.
3. Channel id: open the channel in [web.telegram.org/a](https://web.telegram.org/a/); the address ends with
   `#-100…`. That number (with the minus) is `STATE_CHAT_ID`.

### 2. `.env`

Copy `.env.example` to `.env` (already done in this folder) and fill in `TELEGRAM_TOKEN`, `REGION`,
`STATE_CHAT_ID`.

### 3. Inverters

For each Deye Cloud account:

1. Sign in at [developer.deyecloud.com](https://developer.deyecloud.com) with that account, create an
   application, copy **AppId** and **AppSecret**.
2. Run `Deye token.bat`, enter AppId, AppSecret, login, password. It shows the inverter's data and how long
   the token is valid, and writes `DEYE_n_*` into `.env`.
3. `DEYE_n_OWNER_CHAT`: the chat that gets this inverter's alerts. After the bot is running, send it `/myid`
   from that chat and put the number into `.env` (then re-upload the Secret File).

When the token is about to expire, the bot warns the owner 7 days ahead. Run `Deye token.bat` again with the
same slot number and re-upload `.env`.

### 4. GitHub

Private repository `Shutdown_Checker` with everything in this folder except what `.gitignore` excludes
(`.env`, state files). Check before the first push that `.env` is not listed.

### 5. Render

1. [dashboard.render.com](https://dashboard.render.com) → **New** → **Web Service** → connect GitHub →
   pick `Shutdown_Checker`.
2. **Language / Runtime:** Docker. **Branch:** main. **Region:** Frankfurt (EU Central).
   **Instance type:** Free.
3. **Advanced → Health Check Path:** `/health`.
4. **Environment → Secret Files → Add Secret File:** filename `.env`, contents: paste the whole local `.env`.
   Do not add these values as plain environment variables; one Secret File is enough.
5. **Create Web Service.** In **Logs** you should see
   `webhook mode: https://<name>.onrender.com/telegram … state in pinned document …, N inverter(s)`.
6. After every change of `.env`: edit the Secret File, then **Manual Deploy → Deploy latest commit**
   (or restart the service).

### 6. Keep it awake

The free service sleeps after ~15 minutes without requests; while asleep it sends no reminders.
At [cron-job.org](https://cron-job.org) (free): create a job `GET https://<name>.onrender.com/health`
every **10 minutes**. One always-on free service fits Render's 750 free hours per month.

## Run locally

`Run locally.bat` reads the same `.env` and runs in polling mode (no public URL). Without `STATE_CHAT_ID`
the state is kept in `bot_state.json`. Do not run it with the same bot token as the Render service.

## Test

```
py tests\test_e2e.py
```

Starts the bot in webhook mode against fake Telegram and Deye servers and checks commands, owner-only
inverter alerts, token expiry warning, read-only Deye calls, state save and restore after a restart.
